### nan problem in PPO training

1. evaluation config in `PPOConfig`

    经过debug发现，reward=nan 对应的是evaluate过程中的reward，在原PR中并未添加eval，故添加evaluation config，但是这将会调用默认的evaluate，而其自定义的env并不支持原生evaluate的调用（报错）

2. add custom evaluate function 

    通过添加自定义的evaluate，可以在training log中观察到相应的eval输出，但是在training log table中，仍然显示为nan，可以确认的是evaluate函数确实覆盖了默认的evaluate，被正确的执行

3. inject the eval result to metric_queue

    发现问题的核心是：`metric_queue`没有被正确的更新
    
    原生的`self.evaluate`使用的是`self.evaluation_workers`来生成batch数据。workers中有对应的`sampler`，`sampler`中会保存`self.metrics_queue`，所以原生的`self.evaluate`去`collect_episodes`时，会去调用`rollout_workers`的`get_metrics`，来获取`self.metrics_queue`的值，也就是说在自定义的`evaluate`中也需要这么一个过程



### training workflow in RLlib

rllib中比较核心的类是Algorithms，其包含了train step和eval step这两个主要过程，负责实际任务执行的是rollout workers，local workers负责梯度更新，remote workers负责generate experience，并生成batch数据

![](/img/ppo-pipeline.png)

1. batch数据在rllib中的实现如下

    ```py
    sample_batches = worker_set.foreach_worker(
        lambda w: w.sample(), local_worker=False, healthy_only=True
    )

    # ...

    # concate and return
    all_sample_batches.extend(sample_batches)
    full_batch = concat_samples(all_sample_batches)
    return full_batch
    ```

2. batch数据会被传入到train_one_step中

    ```py
    train_results = train_one_step(self, train_batch)
    ```

3. updated the local policy 并且将其更新至 remote worker中

    ```py
    self.workers.sync_weights()
    ```

4. Metrics reporting

    ```py
    metric_lists = workers.foreach_worker(
        lambda w: w.get_metrics(),
        local_worker=True,
        remote_worker_ids=remote_worker_ids,
        timeout_seconds=timeout_seconds,
    )
    ```
