# Gather-scatter

## 背景
[Gather-scatter](https://en.wikipedia.org/wiki/Gather-scatter_(vector_addressing))是一种矢量寻址方式。这种模式适用于对地址不连续的若干元素做相同计算。典型计算如
```c++
// gather
for (i = 0; i < N; ++i) {
  x[i] = y[idx[i]];
}
// scatter
for (i = 0; i < N; ++i) {
  y[idx[i]] = x[i];
}
```

在XGBoost的实现中，将样本的grad和hess值叠加到对应的hist中属于这类模式。hist在内存中是连续地址的若干个浮点数，所以统计过程是将样本的grad和hess值叠加到所有特征对应的bin中。由于样本的特征是随机的，所以访问的bin是随机的。当前版本的实现中是采用循环的方式，每次将一个样本的grad叠加到对应的bin内。这个循环前后无依赖，可以被展开成向量化运算。gather指令收集需要计算的元素，add指令叠加，scatter指令写回。

## 代码
```c++
union Index {
    __m512i u;
    int s[sizeof(__m512) / sizeof(int)];
};
```
```c++
void roll(const Index* vindex, float* base_addr, int N) {
    for (int i = 0; i < N; i++) {
        for (int j = 0; j < sizeof(__m512) / sizeof(int); j++) {
            base_addr[vindex[i].s[j]] += base_addr[vindex[i].s[j]];
        }
    }
}
```
```c++
void vectorization(const Index* vindex, float* base_addr, int N) {
    for (int i = 0; i < N ;i++) {
        auto result = _mm512_i32gather_ps(vindex[i].u, base_addr, 4);
        result = _mm512_add_ps(result, result);
        _mm512_i32scatter_ps(base_addr, vindex[i].u, result, 4);
    }
}
```
```c++
void prepare(Index* vindex, float* base_addr, int N, int LEN) {
    std::random_device rd;
    std::default_random_engine e(rd());
    std::uniform_int_distribution<unsigned> rindex(0, LEN-1);

    for (int i =0 ; i < LEN; i++) base_addr[i] = e();
    for (int i = 0; i < N; i++){
        for (int j = 0; j < sizeof(__m512) / sizeof(int); j++) {
            vindex[i].s[j] = rindex(e);
        }
    }
}
```
```c++
int main(int argc, char** argv) {
    const int LEN = 1000000;
    volatile int N = 100000;

    float * base_addr = new float[LEN];
    Index vindex[N];
    prepare(vindex, base_addr, N, LEN);
    roll/vectorization(vindex, base_addr, N);
}
```

## 分析
未开启O3优化的编译产出roll函数是完整的两重循环，指令数多于vectorization，开启O3优化后的编译产出对内循环做了循环展开，少了内循环判断的计算，指令数虽然也多于vectorization，但是指令周期较短，所以roll整体时间略短于vectorization。但是整体来看，由于gather/scatter引入了额外的计算，在计算负载较轻的场景下，overhead cost抵消了指令减少带来的收益，所以在部分条件下vectorization的运行时间甚至会低于roll。

另一方面，上述测试代码表示循环N次实验，理论上运行时间仅与N有关，但是实验结果显示运行时间在N不变的情况下还与寻址范围相关。测试模拟了实际场景随机寻址，当寻址范围增大时，缓存命中率会下降。实际测试开启O3优化，len=1000时，Cache Bound: 1.7% of Clockticks，len=1000000时，Cache Bound: 81.2% of Clockticks。
