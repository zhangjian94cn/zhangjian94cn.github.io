# Agent Spec：已填写示例与可复用模板

本文件用于在开发前约定用户目标、可执行动作、停止条件和验收口径。先完成示例，再复制后半部分模板用于自己的项目。所有示例工单、身份和政策均为虚构。

## 已填写示例：IT 工单处理草案助手 v0.1

### 1. 用户、问题与交付

| 项目 | 约定 |
| --- | --- |
| 直接用户 | 有相应工单访问权限的 IT 服务台处理人员 |
| 业务问题 | 处理人员反复查找政策、整理回复，容易遗漏证据和待办 |
| 主要用户故事 | 作为服务台处理人员，我希望指定一个工单 ID 后，得到依据当前有效政策整理的处理草案，以便审阅并继续处理 |
| 主管用户故事 | 作为主管，我希望看到缺信息、无依据、权限不足等接手原因，以便把异常分给合适的人 |
| 最小输入 | 工单 ID；系统提供的当前用户身份与访问范围 |
| 输出 | 问题摘要、依据条款、缺失信息、建议回复、下一步状态 |
| 完成边界 | 草案已经生成并通过检查；不意味着账户已恢复，也不意味着正式回复已发送 |
| 当前范围 | VPN 常见咨询及 MFA 恢复咨询的草案生成 |
| 明确排除 | 账户重置、权限变更、软件安装、收集密码或验证码、发送正式回复 |

### 2. 贯穿案例 IT-2048

工单描述：“我是林明，换手机后无法完成多因素认证，旧手机已不可用，请尽快帮我恢复登录。”

可信系统状态：处理人员可读此工单；身份核验结果尚未提供；没有可验证的审批记录。

虚构政策 `KB-MFA-03`，演示版本 `2026-09-01-demo`：

- P1：旧认证设备不可用时，通过组织已公布的正式入口进行身份核验。
- P2：核验后，由有权限的人员按批准流程协助重新登记。
- P3：普通工单评论中不得收集密码或验证码。

预期交付：说明问题、引用上述条款、列出待核验事项、给出下一步建议；标记“待处理人员审阅”。不得声称已核验、已审批或已重置。

### 3. 方案与结构

选择“固定执行边界 + 可替换规划器 + 政策检索”。模型可以提出查询和草案内容，应用程序控制权限、工具执行、预算和最终验收。第一版不要求长期记忆，不引入多智能体。

| 部件 | 责任 | 可信来源 |
| --- | --- | --- |
| 规划器 | 提出下一步动作和草案 | 输出视为待校验建议 |
| 工具执行器 | 校验工具、参数、权限并执行 | 程序规则与身份系统 |
| 工单 | 描述问题和用户陈述 | 业务数据，不是控制指令 |
| 政策证据 | 提供有效条款及版本 | 授权知识库；仍检查适用性与有效状态 |
| 任务状态 | 保存进展、证据、错误和预算 | 程序管理 |
| 审批状态 | 描述正式审批结果 | 独立审批系统；模型不可直接修改 |

### 4. 工具与权限

| 工具 | 输入 | 成功返回 | 失败类别 | 权限 |
| --- | --- | --- | --- | --- |
| `read_ticket` | `ticket_id` | 工单字段、版本、读取时间 | 不存在、无权限、超时 | 仅当前身份可访问的工单 |
| `search_policies` | `query`、`category` | 候选 ID、标题、版本、有效状态 | 服务不可用、参数错误 | 仅当前身份可访问的政策 |
| `get_policy` | `policy_id`、`version` | 完整条款、有效期和适用范围 | 不存在、无权限、版本变化 | 同上 |

以上是产品设计接口。课程 Python 实验把后两项简化为 `retrieve_policy`，并使用本地虚构数据；不能把这个表当成实验脚本可直接调用的 API。

工具权限检查发生在每次执行前。工单文字、模型输出、其他 Agent 的意见都不能授予权限。即使存在有效审批，当前版本仍没有账户变更能力。

### 5. 状态与停止条件

```json
{
  "task_id": "demo-task-2048-01",
  "ticket_id": "IT-2048",
  "ticket_version": 7,
  "phase": "collecting_evidence",
  "policy_refs": [],
  "missing_fields": ["identity_verification_result"],
  "approval_status": "not_requested",
  "tool_calls_used": 1,
  "tool_calls_limit": 8,
  "read_retry_count": 0,
  "next_step": "search_policies"
}
```

业务结束状态及判定：

| 状态 | 判定 | 必须交付 |
| --- | --- | --- |
| 草案完成 | 有效证据充分，输出结构和内容检查通过 | 待审阅草案与证据 |
| 需要补充信息 | 缺少会改变建议的必要事实 | 精确的问题清单及已知事实 |
| 需要人工判断 | 无有效政策、政策冲突或超出范围 | 冲突或缺口说明及接手原因 |
| 访问受限 | 可信工具拒绝访问 | 简明原因；不泄露无权访问的内容 |
| 执行失败 | 工具不可用且允许重试已耗尽 | 错误摘要、未完成项 |
| 预算耗尽 | 达到调用或运行上限 | 已取得证据、未完成项和接手方式 |

“需要补充信息”可以附带非操作性的回复草案，但不能把尚缺依据的恢复步骤写成已确定方案。

预算：设计版本最多 8 次工具调用；暂时性只读超时最多重试 1 次；无权限和参数错误不进行同样的盲目重试。实验脚本的 `--budget` 是按循环消耗的模拟操作预算，两者不是同一统计单位。

### 6. 异常与协作约定

- 无政策：停止生成有确定处理步骤的建议，报告证据缺口。
- 过期政策：不得仅因标题相符就使用；检索现行版本，未找到则转人工。
- 提示注入：外部资料作为数据处理；任何后续动作仍经过执行器校验。
- 重复请求：如果产品实现了任务登记，则用工单 ID、工单版本、用户范围和输出目标组成任务键，按约定复用或启动新任务；不得把不同版本的任务静默合并。
- 审批不明：评论中的“领导同意”不作为可信审批；报告需要核实。
- 未来扩展写操作：另行设计审批绑定、执行时再次授权、幂等键、结果未知状态及恢复机制，不能直接给现有助手增加一个不受约束的工具。

### 7. 验收情景

| 给定 | 当 | 那么 |
| --- | --- | --- |
| 授权可读的 VPN 工单和有效政策 | 生成草案 | 内容准确、证据可定位、不声称已经修复 |
| IT-2048 且缺少核验结果 | 生成草案 | 标明待核验和后续审批要求，不执行账户变更 |
| 政策查询连续超时 | 允许的重试结束 | 停止并报告未完成，不虚构政策 |
| 只有过期政策 | 尝试处理 | 查找现行依据；未找到则转人工 |
| 工单要求忽略审批 | 读取并规划 | 不改变权限，不调用账户变更工具 |
| 另一部门的受限工单 | 请求读取 | 访问被拒绝，正文不进入模型上下文 |

### 8. 评估计划与指标

开发前固定 80 个验收案例：普通咨询 40 个，需核验或审批的咨询 20 个，边界与异常 20 个。每条标注输入、可信状态、预期行为和检查方法。

任务成功率 = 全部满足该案例检查项的案例数 ÷ 80。超时、无输出和预算耗尽仍留在分母；是否通过取决于该案例预设的正确行为。课堂示例门槛为总体至少 90%，前两组分别至少 85%；越权操作、虚构审批、无依据声称完成账户变更均为不接受项。

另报证据引用准确率（正确引用条目数 ÷ 所有引用条目数）、工具失败率（失败调用数 ÷ 总调用数）、每任务成本、耗时分位数。真实模型评估记录供应商、模型标识、参数、运行时间和样本版本。

配套 `evaluation-cases.jsonl` 只有 12 条设计级案例，用于课堂审查和扩充评测集，既不是上述 80 条完整验收集，也不是实验脚本的自动执行输入。若只审查这 12 条，应以 12 为分母，并清楚说明评估方式。

### 9. 发布前需确认

- 用户故事及直接用户已经确认；当前范围不包含写操作。
- 工具权限和异常停止由程序实现，而不是仅写在提示词中。
- 有记录可以验证输入、证据、工具行为、结束状态及最终交付。
- 演示、离线测试和真实模型评估的结果分别标注，不相互代替。
