# 架构与执行决策记录

这份模板用于记录“为什么选这个方案，以及什么证据会让我们重新考虑”。一条记录解决一个具体问题，不把整份项目说明塞进去。没有真实实验结果时，标记为假设或待验证。

| --- | --- |
| 决策编号 | ADR-001 |

| 状态 | 教学示例，待项目评审 |
| 日期 | 2026-09-21（示例） |
| 决策人 | 项目负责人（占位） |
| 关联 Spec | IT 工单处理草案助手 v0.1 |
| 要解决的问题 | 是否需要分别设置分类、检索、政策解释和审批 Agent |

### 当前事实

- 第一版只处理 VPN 和 MFA 恢复咨询，输出待审阅草案。
- 所有工具只读；身份与审批事实由可信系统提供。
- 通常一次读取工单、少量政策查询即可形成草案。
- 尚未进行真实模型对比评估，无法声称多智能体已提高质量或降低成本。

### 候选方案

| 方案 | 预期收益 | 代价与失败点 | 验证方式 |
| --- | --- | --- | --- |
| 固定工作流 + 政策检索 | 步骤清楚、容易复盘 | 对需要自适应追问的任务可能不够灵活 | 先跑完整设计案例集 |
| 单规划器 + 固定执行边界 | 可根据观察决定查询或停止 | 仍需检验规划质量与工具选择 | 与固定流程在相同案例上比较 |
| 主管 + 多个专家 Agent | 可能适合跨领域并行分析 | 增加上下文传递、结果冲突和协调成本 | 只有出现明确跨领域需求后再验证 |

### 本次选择与理由

采用单规划器与固定执行边界。当前任务尚未显示出多个独立专家的必要性；工具权限、证据有效性、停止条件更影响交付可靠性。保留规划器接口，先用规则模拟器演示运行机制，后续再单独评估真实模型。

### 影响与约束

- 第一版不展示虚构的“专家协作能力”。
- 工具接口和状态需要清楚，便于以后替换规划器。
- 如果同一任务确实需要独立的网络和身份专业判断，可以新增并行分析实验；不能直接把实验结果当作正式效果。

### 什么证据会触发重新讨论

至少积累一批跨领域任务，能说明单规划器的具体失败原因；在固定样本上比较任务成功率、耗时和成本；如果多智能体有稳定收益且没有扩大不可接受错误，再考虑改变架构。比较门槛应在实验前确定。

### 当前验证状态

未进行真实模型架构对比。当前选择是根据任务范围作出的设计决策。
