模块 02 / 多智能体系统的概念与结构

第 5 课：什么时候值得使用多智能体？

建议学习 25 分钟（含练习） · 本课产出：架构选择记录
返回课程总览5 / 16

场景：一个工单，真的需要五个“专家”吗？

员工提交了工单 IT-2048：“换了手机，现在无法完成多因素认证，急着登录系统开会。”你给助手安排了需求分析师、身份专家、政策专家、方案专家和审核专家。屏幕上五个角色轮流发言，看起来像一支团队，但用户等了一分钟，得到的仍是“请联系管理员”。

问题不在于角色不够多，而在于分工是否带来了实际收益。本课程中的企业、工单和 KB-MFA-03 政策均为教学假设。政策要求：涉及敏感账户变更，必须经过独立身份核验与人工审批。助手的当前任务是读取工单、检索政策、生成处理草案。

交互演示 / 并行耗时

多开一个执行者，能省多少等待？

仅两个中间任务可并行，其他步骤固定串行。这里计算耗时，不估算模型效果或价格。

公式：依次 = A + B + 其他；并行 = max(A, B) + 其他。单 Agent 也可以并行调用工具，因此不能只凭这个结果决定采用多 Agent。

先区分三个容易混在一起的概念

多次调用模型，不一定是多智能体。把同一份材料先总结、再润色、再输出，可以只是固定工作流。

多个工具同时运行，也不一定需要多智能体。一个助手可以并行读取工单历史和政策文档，再统一推理。

在本教程中，多智能体系统指多个具有明确职责边界、上下文和可执行决策范围的 Agent，通过任务与消息协作完成目标。它们可以使用同一款模型，也可以运行在同一进程。这里是工程上的约定，并非唯一学术定义。关键是：谁负责什么，能决定什么，结果如何汇合。

一个足够实用的选择表

任务特点 优先尝试 判断理由
单一目标、工具少、规则明确 单 Agent 上下文集中，定位问题容易
步骤固定，分支可枚举 确定性工作流 不必让模型决定已经确定的路径
只是几个读取动作互不依赖 单 Agent 并行调用工具 并发本身不要求多个决策主体
多个可独立完成的子任务，证据需要分别整理 多 Agent 候选 分工可能减少等待并保持上下文聚焦
子任务工具权限、专业知识或责任不同 多 Agent 候选 职责隔离有明确价值
每一步都必须依赖前一步的完整结果 先保持单 Agent 拆分可能只增加交接成本

对 IT-2048，最小版本可以只有一个助手。它读取工单与政策，把“用户陈述”和“已验证事实”分开，发现身份核验缺失后，生成补充材料清单和待审批草案。

当系统同时处理数百类工单，需要一个专家核对身份政策、另一个专家分析设备兼容性时，多 Agent 才有更明确的试验价值。两个专家都只能读资料和提建议；把名字改成“管理员 Agent”不会自动赋予账户操作权限。

算一笔账：并行到底省了多少时间？

下面所有时长、用量和单价都是教学假设，不代表任何厂商报价或性能。比较时假设任务和验收标准相同，不计网络波动与重试。

环节 依次执行 专家并行执行
分析与分派 3 秒 3 秒
身份政策核对 18 秒 18 秒，与设备核对并行
设备信息核对 10 秒 10 秒，与政策核对并行
汇总草案 10 秒 10 秒
检查输出 8 秒 8 秒
总时长 49 秒 39 秒

并行总时长是 3 + max(18, 10) + 10 + 8 = 39 秒，节省约 20.4%，而不是“两个专家就快一倍”。只有中间两项能够并行，其他步骤仍在关键路径上。

再假设输入每百万 Token 为 1 美元，输出为 4 美元。原方案累计输入 14,000、输出 2,000 Token，模型费用为 0.014 + 0.008 = 0.022 美元。拆分后因重复背景、专家回复和汇总，累计输入 22,000、输出 3,000 Token，费用为 0.022 + 0.012 = 0.034 美元，增加约 54.5%。这些用量是假定的调用日志总量，并非从时长推算，且未包含工具和基础设施费用。

更关键的是：单 Agent 也可能并行完成这两个读取动作，获得接近的等待时间。因此，这个算例只能证明并行有价值，不能单独证明多 Agent 有价值。

本课产出：一页架构选择记录

写下目标、候选架构、预计收益、额外成本和回退条件。用同一批脱敏工单比较完成率、证据正确率、人工返工率、P95 耗时和每个成功任务的成本。P95 耗时表示约 95% 的任务在这一时长内完成。初期可用 30 条工单做冒烟比较，但不能据此宣称所有场景都有效。

练习：你会怎么拆？

现在只处理“更换手机后 MFA 不可用”，政策固定，每天 20 单。有人建议先做五个 Agent，并规定它们至少讨论三轮。请给出第一版架构和升级到多 Agent 的条件。

展开参考答案 · 先试着自己回答

第一版采用单 Agent 加明确工作流：读取工单 → 检索政策 → 列出事实与缺失项 → 生成草案 → 等待身份核验与人工审批。允许独立读取动作并行，不要求模型凑满讨论轮次。

当评测发现上下文混杂、专业规则明显不同，或独立子任务确实造成主要等待时，再试验专家拆分。是否保留拆分，以同等验收标准下的质量、耗时和成本结果决定。不能把“角色更多”当成升级成功的证据。
