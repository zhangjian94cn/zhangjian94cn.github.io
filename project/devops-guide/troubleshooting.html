故障速查

本页目录环境、进程与权限网络与 HTTP健康、数据库与数据Git、镜像与流水线IaC、集群与 GitOps观测、门禁与异步任务一条足够好的求助记录

先确定影响与发生层次，再选择最小的检查动作。保存时间、命令、退出码和脱敏日志。不要把删除环境、放宽权限或关闭验证当成默认第一步。

本页命令默认位于自己的 ticketdesk/ 本地实验目录，工单 ID 和端口按实际配置替换。真正需要删除数据的动作不放在快速修复命令里。

环境、进程与权限#

症状 先检查 判断与下一步
docker 不存在 python3 scripts/lab.py doctor 安装适合操作系统的 Docker；只有 CLI 还不够，需要 daemon 可用
CLI 存在但连接不上 daemon docker info 检查服务或桌面运行时是否启动、当前 context；不要直接扩大 socket 权限
compose 子命令不存在 docker compose version 安装受支持的 Compose v2；教程不使用旧的独立 docker-compose 路径
端口已占用 Linux 用 ss -ltnp，macOS 可用 lsof -i :8000 判断已有进程属于谁；修改本项目端口或停止自己确认的旧实例
app 一启动就退出 docker compose ps -a app 与 app 日志 看退出码、导入失败、启动参数、配置与权限，不先怀疑网络
文件 Permission denied id、目标文件与父目录权限 同时检查运行身份、目录遍历权限、挂载是否只读
本地依赖导入失败 .venv/bin/python -m pip --version 确认安装和执行使用同一个解释器，避免把包装进另一个 Python
进程响应慢或被终止 docker stats --no-stream、宿主机资源与日志 区分 CPU、内存、磁盘、句柄与依赖等待；不能仅靠增加重启次数

网络与 HTTP#

症状 先检查 判断与下一步
域名不能解析 检查当前环境中的 DNS 结果 本机与容器解析视角不同，Compose 内使用服务名
Connection refused 服务是否监听、端口映射与进程状态 通常没有可接受连接的监听端点，或收到主动拒绝；先查服务
请求超时 连接是否建立、目标地址、网络策略、依赖耗时 超时是等待超过限制，不是单一根因
证书错误 域名、有效期、信任链与系统时间 修复具体原因；不要将 curl -k 写入常规验证
代理返回 502 直连 app 与代理日志 检查上游地址、端口、协议和连接状态
代理返回 504 后端耗时与代理超时 找出等待在哪一层，不仅是提高代理超时
HTTP 422 请求 JSON 与字段约束 TicketDesk 标题去空白后至少 3 字，priority 是 low/normal/high
HTTP 404 实际工单 ID 与路由 创建验收工单会消耗 ID，不要假定第一条永远是 1

对比直连与代理：

curl -i http://127.0.0.1:8000/health/ready
curl -i http://127.0.0.1:8080/health/ready
docker compose logs --tail 50 app
docker compose --profile proxy logs --tail 50 proxy

只有已启动 proxy profile 时才检查 8080。两个入口都失败，先检查共同依赖；直连成功而代理失败，再集中排查代理路径。这个顺序可以减少无目的地修改配置。

健康、数据库与数据#

症状 先检查 判断与下一步
live 200、ready 503 app 日志、db 状态、最近配置与迁移 进程仍在，依赖或 schema 不满足条件；查连接、身份、表与字段
工单接口 503 请求 ID 对应日志与数据库状态 本例把存储错误转成通用 503；不能仅凭状态码区分所有根因
数据库密码修改后失败 是否更改 .env，是否沿用既有卷 初始化配置与已有数据库身份不同步时，需要按数据库账号流程修复；删除卷不是默认答案
缺表或缺字段 schema_migrations 与迁移日志 确认迁移先于应用启动，且迁移使用预期候选镜像
migration checksum mismatch 已应用 SQL 文件是否被修改 恢复历史迁移内容，用新文件表达新变化，不直接篡改记录表
迁移锁超时 是否有并发迁移或长事务 找到锁持有者与执行上下文，避免多个自动重试任务继续竞争
重建后“数据没了” Compose 项目名、实际卷、数据库名 先判断是否连到了新卷或新库；不要继续清理可能含原数据的资源
备份有文件但恢复失败 文件非空、格式、版本、恢复日志 在新数据库验证，保留原库；单看文件大小不证明备份有效
恢复对比不一致 备份后源库是否继续写入 先区分时间差与恢复错误，再核对具体业务字段

人为注入的错误数据库主机名，使用项目恢复入口修复：

python3 scripts/lab.py recover
python3 scripts/lab.py check --ticket-id 1

这只适用于本教程已记录健康镜像的实验。它不撤销迁移，也不从备份恢复数据。如果错误来源不同，应先判断该动作是否适用。

Git、镜像与流水线#

症状 先检查 判断与下一步
修改代码但容器行为没变 当前运行镜像与构建时间 源码没有自动进入既有镜像，按流程重建并替换
同名标签行为不同 各环境实际 digest 与平台 tag 可能移动；记录并部署明确的制品身份
PR 页面没有 Actions 检查 工作流是否在仓库根 .github/workflows，事件条件是否匹配 下载项目应成为独立仓库根，不是只把它放进子目录
GHCR 推送被拒绝 失败步骤、包权限、组织策略与镜像名称 限定到所需仓库和包权限，不默认申请管理员权限
CI 通过但本机失败 解释器、架构、依赖、配置、端口与已有数据 临时空库与长期保留库可能走不同路径
workflow 一直等待或被替换 concurrency group 与触发条件 互斥控制不是任意数量的严格发布队列
回退后仍然错误 旧镜像是否真的可获取、配置与数据库是否兼容 应用、配置与数据需要分别检查
Git 出现秘密文件 先停止继续传播，按凭据所有者流程撤销或轮换 仅从当前版本删除不能消除历史中的凭据

IaC、集群与 GitOps#

集群检查先确认 context 与命名空间。以下对象名来自实验配置，实际名称和权限按自己的环境核对；只读取故障状态，不默认删除资源。

症状 先检查 判断与下一步
IaC plan 想替换意外资源 资源地址、变量、state 所有权与 provider 版本 暂停 apply，区分合法迁移与错误关联；不先删 state
state 锁未释放 锁的任务 ID、所有者、运行状态 确认没有活跃写入再按后端规程恢复，避免并发损坏
Ansible 第二次仍大量变更 具体 changed 任务、模板内容和模块行为 区分必要变更与不稳定输入；check 模式不能代替两次真实运行
Pod Pending describe 中调度事件、request、节点和 PVC 判断容量、亲和、污点或存储绑定，不先提高重试次数
ImagePullBackOff 镜像引用、平台、拉取身份与 registry tag/digest 存在、权限和网络分别验证
CrashLoopBackOff 当前及 previous 日志、退出码、配置 分清程序崩溃、探针杀进程与资源终止
Running 但不 Ready readiness 结果、依赖、迁移与 Secret 容器启动成功不等于可接收业务流量
Service 没有可用端点 selector、Pod labels、EndpointSlice 和就绪 对照实际标签；不要修改 Pod IP 作为永久修复
Gateway 没流量 Gateway/Route 条件、引用与真实入口服务 ResolvedRefs 或 Accepted 失败可能发生在应用之前
NetworkPolicy 没有效果 CNI 是否执行、选择器、请求实际路径 用普通 Pod 请求做正反例；port-forward 不证明策略隔离
HPA 显示 unknown 指标 API、Pod 指标、资源 request 先恢复测量基础，不能仅增加最大副本
drain 等待不结束 PDB、可用副本、容量、卷约束 找到被保护的业务条件，不默认强行驱逐
GitOps 不同步 repo 权限、路径、revision、AppProject 和差异 区分获取、渲染、授权与应用失败
手工回退后又变回新版本 Git 期望状态、self-heal 和同步策略 通过受审查提交修正期望状态，保留事件记录

观测、门禁与异步任务#

症状 先检查 判断与下一步
Prometheus 目标 down targets 状态、容器 DNS、端口与 metrics 路径 抓取失败不同于业务错误；分别观察
面板没有数据 时间范围、标签、查询窗口及是否有请求 无数据不应自动解释为零错误
p95 不合理 histogram 桶、rate 窗口、样本与分组 不用均值代替 p95，不聚合不兼容的桶
trace 看不到 插桩是否启用、采样、导出地址、Collector pipeline 按生成到接收的顺序排查；不伪造 trace ID
告警触发但无人收到 pending/firing、路由、抑制/静默、接收器和投递结果 本例没有外部接收者，必须另做端到端通知验证
扫描报告“空” 扫描退出码、目标、Results、数据库时间 扫描失败不能当无漏洞；缺失结果应阻断
签名可验证但身份不对 issuer、identity、subject digest 与策略 密码学验证成功不等于符合你的发布授权
规则 YAML 可解析但部署仍被拒 API 版本、准入策略、RBAC 与实际对象 解析不验证集群语义，按拒绝原因分层修复
事件重复计数 稳定 event ID、去重记录与事务边界 标记和同库效果需一起提交；外部副作用另处理
AI 评测组合不符 bundle 的数据集摘要与模型/Prompt 版本 修正受评审的发布组合，不绕过摘要检查
AI 输出结构正确但业务错误 独立案例与类别混淆、语义评价 schema 校验只管结构；补真实质量门禁和降级

一条足够好的求助记录#

使用这样的结构，能帮助别人快速复现：章节与小节；操作系统、架构和工具版本；命令执行目录；脱敏后的命令；退出码；实际与预期行为；最近一次成功状态；已经尝试的动作；数据是否需要保留。

不要上传 .env、完整连接串、token、私钥或真实业务数据。对错误只截最后一行常常缺少上下文，可以提供明确时间窗口内的脱敏日志，并保留 request ID、步骤名和版本身份。
