01—04：认识交付全流程#

章节 参考答案与检查重点
01 交付全流程 责任表应覆盖需求、代码、测试、制品、部署、运行反馈，并把负责人和证据放在同一行。等待点改善要有前后窗口和可观察结果；增加一个工具不自动说明等待减少。
02 环境 CLI 成功、daemon 失败先检查服务与连接权限；单元测试成功、镜像拉取超时检查 DNS、代理、registry 与网络；启动正常却访问错误端口先比对监听和端口映射。三者都不足以推出业务逻辑错误。
03 运行项目 保存创建响应、ID、版本和 request ID；重启后读取同一记录证明持久性的一部分；非法输入被拒绝证明边界检查。必须说明真实数据库是否参与，不能拿替身测试证明持久化。
04 需求 状态过滤 Issue 要列合法/非法状态、空列表、无参数行为、排序和兼容性。分页可明确排除在首版之外，但应说明当前数据规模与未来触发条件；ADR 记录依据和后果，不只是选项名称。

05—08：系统、网络与自动化#

章节 参考答案与检查重点
05 权限 读取文件需要对父目录路径具有搜索权限。文件 644 不能绕过父目录 700；先确认实际 UID/GID、路径与挂载，按所需访问授予最小权限，不能用 777 掩盖身份或目录设计错误。
06 进程 单元启动只说明管理器状态；监听说明对应进程绑定端口；创建成功还涉及路由、输入、依赖和数据。分别查 unit/journal、监听与进程、请求和数据库证据。重启风暴应追查退出原因。
07 网络 直接请求应用成功、代理请求失败，把范围缩到代理入口、上游地址或代理到应用路径。用配置与连接证据确认错误端口；浏览器一句“失败”不能排除 DNS、TLS、HTTP 或业务错误。
08 脚本 健康等待要有截止时间、每次请求超时、有限重试和非零失败退出；业务创建可能有副作用，不应无幂等键自动无限重试。候选失败时不更新成功记录，否则恢复会再次选中坏版本。

09—12：Git、测试与 CI#

章节 参考答案与检查重点
09 协作 共享分支撤销一般新增可审查的反向提交，保留历史；解决冲突后必须重新测试语义。Git 撤销不改变已运行进程，更不会自动恢复数据库。PR 的测试和评审要对应最终提交。
10 依赖 新虚拟环境重建需要记录解释器、完整依赖和 pip check；锁定包版本仍不能锁定 OS、基础镜像和远端服务。相同依赖却结果不同，应继续比较运行时、平台与配置。
11 测试 正例证明目标行为，负例证明错误被拒绝，兼容例证明旧调用仍有效。内存替身不能发现 SQL 语法、真实约束、事务锁和连接失败；这些要放进数据库集成测试。故意改错后测试必须失败才有证据。
12 流水线 将本地同一检查交给 CI，明确触发、依赖和权限；失败阻止候选晋级，但诊断与临时资源清理尽力执行。仓库合并规则也要绑定正确检查，单有 YAML 不保证失败 PR 不能合并。

13—16：容器与制品#

章节 参考答案与检查重点
13 容器 exec 成功仅说明能在容器内执行进程；代码未重建镜像时仍可能运行旧内容；自动重启不会修正错误数据库地址。把应用程序、运行进程、配置与外部数据分别检查。
14 镜像 多阶段构建减少运行阶段内容，但必须验证运行依赖完整、用户权限正确和写目录可用。构建成功不代表容器能够启动。不要把 Secret 写进构建参数或层，再以删除文件代替消除历史泄漏。
15 Compose 启动顺序、依赖就绪与迁移完成是不同条件。应用用服务名找数据库；容器内 localhost 指自己。重建应用后查询旧工单，才能检查卷与数据路径；删除卷会改变实验前提。
16 digest 可变 tag 可以指向新内容，固定 digest 仍标识原对象。可识别不代表可获取，回退还需要 registry 保留、目标平台支持、配置及数据兼容。本地 image ID 与 registry manifest digest 不应混用。

17—20：第一次交付与恢复#

章节 参考答案与检查重点
17 候选发布 失败测试后不能推送“已通过”的候选。验证、发布和记录应关联同一次构建；查看失败路径与清理路径。并发取消策略应实测，不能假设运行中的生产部署总可安全取消。
18 部署 成功发布需要环境、镜像与配置身份，加上就绪和业务检查。旧镜像回退与配置修复应分别验证。若新镜像根本未通过检查，最近成功记录应保持不变，并保留失败候选诊断。
19 数据 数据模型兼容包含 schema 与值语义。旧程序无法理解新状态时，切回旧镜像也可能失败。恢复应到新库，暂停写入后按明确口径比较；仅有备份文件不能证明可恢复。
20 运行验收 配置故障与坏应用版本是两种恢复案例，需独立时间线。验证已有工单和新写入；区分命令完成、探针通过与用户路径恢复。短时请求数或均值不能证明长期可靠性。

21—24：云与基础设施#

章节 参考答案与检查重点
21 云边界 托管数据库仍需应用团队验证连接权限、schema、备份策略、恢复后的数据与业务路径；供应商管理机器并不意味着满足你的 RPO/RTO。规划图需要责任、预算和资源清理条件。
22 IaC 名称改变是否替换资源由 provider 属性语义与 plan 决定。不要凭 HCL 文本猜测后直接 apply；恢复原配置再比较计划。销毁应只涉及本练习资源，并确认空卷没有需要保留的数据。
23 state 两个状态文件管理同一数据库会造成所有权冲突，单个后端锁不能跨不同状态解决它。应统一资源所有权并安全迁移关联。state 不是可以随便删除的缓存；导入只建立关联，不自动生成正确设计。
24 Ansible 第二次运行无业务变化是幂等证据之一，还需检查服务与文件状态。check/diff 不是全部模块的真实执行。Secret 预先配置、运行用户受限、handler 必要时触发；远端实验才能证明 SSH、systemd 与重启行为。

25—28：Kubernetes 应用运行#

章节 参考答案与检查重点
25 控制器 Deployment 通过 ReplicaSet 维持 Pod，删除一个 Pod 不等于删除声明的工作负载。启动、存活、就绪探针分别回答不同问题。业务写入与持久数据验证不能由 Running 状态替代。
26 网络 错误 Service selector 导致端点选择问题；错误 HTTPRoute backend 是引用解析问题。按主机名、Gateway、Route 条件、Service、EndpointSlice、Pod 排查；port-forward 成功不证明入口流量路径正常。
27 状态 环境变量形式的 ConfigMap/Secret 更新通常需要替换 Pod 才被新进程读取。旧数据库卷初始化过的密码不会因更改初始化变量自动更新；轮换要协调数据库凭据与客户端，并验证恢复。
28 边界 HPA 需要资源指标与合理 request；RBAC 控制 API 操作，NetworkPolicy 控制适用网络路径，PSA 限制 Pod 配置。网络负例只有在 CNI 确实执行策略且正例可达时才有解释力；不互信租户还需要更多隔离。

29—32：集群交付#

章节 参考答案与检查重点
29 配置组织 对比渲染后的对象，确认只有预期副本和环境值改变；输入 values 正确不保证模板正确。缺少 existingSecret 应失败；渲染通过仍不能证明 Secret 实际存在或镜像可拉取。
30 GitOps Git 不可达通常阻止新的期望状态获取/同步，已运行工作负载不因此立即停止；实际行为还依赖控制器配置。GitOps 下恢复应修正 Git 期望状态，否则手工回退可能被再次协调覆盖。
31 灰度 90/10 是路由权重，有限请求不保证恰好 90 与 10。记录候选和稳定版本、足够样本、粘性/连接影响、错误与延迟。先移走候选流量再删候选，数据库共享意味着两版必须兼容。
32 维护 PDB 约束支持的自愿驱逐，不防止所有节点故障；没有剩余容量、卷无法移动或副本不足时仍会阻塞。etcd 状态、持久卷数据和外部依赖应分别备份恢复，不能互相替代。

33—36：观测与诊断#

章节 参考答案与检查重点
33 信号 创建失败看状态与依赖错误；列表变慢看尾延迟、数据库耗时和饱和；新版本无流量看版本、入口路由与标签。每个问题都要有数据源，不凭一张 CPU 图断言业务原因。
34 指标 counter 计算 rate 时处理重启；p95 用合适直方图计算近似分位，不从总耗时/总请求数求得。没有请求时比例可能无数据，不能一概补零宣称健康。跨副本聚合需保持桶边界和标签口径。
35 追踪 检查是否生成 span、是否采样、是否导出、Collector 是否接收，再查后端与关联字段。没有真实 trace 上下文时不伪造 trace ID；数据库 span 不等于已经采集全部内部 SQL 行为。
36 告警 持续阈值与 for 可减少短抖动，但也增加检测延迟。规则触发、Alertmanager 接收与人员收到通知是三个验收点。本例空接收器不能证明送达；Runbook 必须有具体恢复验证。

37—40：可靠性#

章节 参考答案与检查重点
37 SLO 一百万有效请求、目标 99.9%，预算为 1000 次坏请求；已经 800 次则消耗 80%，剩余 200。改变有效请求分母会改变结果，必须预先定义排除项。预算小于零应如实报告超额。
38 容量 固定资源、版本、数据、负载模型和窗口再比较；首个瓶颈需多信号支持。闭环负载在变慢时自然减小请求速率，不能当恒定到达率模型。连接池与重试都应受数据库容量和总超时约束。
39 灾难准备 RPO 看可恢复数据点，RTO 看服务恢复到业务可用所用时间；两者不是同一数。恢复依赖还包括密钥、DNS、镜像与权限。PITR 需要基础备份及连续日志链，普通 dump 不能任意时间点恢复。
40 事件 先确认影响并缓解，记录事实与当时假设，避免用事后知识指责操作者。时间线标明 UTC、动作和证据。改进项应有负责人、期限和完成判据；“以后更小心”无法验收。

41—44：安全交付#

章节 参考答案与检查重点
41 身份 CI、部署器、应用和人员使用不同身份。OIDC 能减少长期密钥，但信任条件过宽仍可能越权；绑定仓库、分支/环境及 audience，并做拒绝测试。轮换完成要检查新凭据有效、旧凭据失效和服务恢复。
42 扫描 高危发现不是孤立分数，应关联目标 digest、包、可利用条件与数据库时间。例外须限定发现、包和制品，有负责人及到期日；过期必须重新阻止。模拟发现只能证明门禁逻辑，不能证明真实镜像无漏洞。
43 证明 digest 校验内容标识，签名验证身份与完整性，provenance 描述构建来源，SBOM 描述组件。验证必须限定预期签发者与构建身份，并确认 subject 对应制品；“有一份签名”不等于可信或达到某个 SLSA 等级。
44 策略 离线 YAML 检查可以在 CI 提前拒绝，但绕过 CI 的写入仍需准入与授权防护。正例只证明所列规则；不检查真实镜像存在性、签名或运行漏洞。策略变更也要测试，例外必须可追踪并到期。

45—48：团队与综合项目#

章节 参考答案与检查重点
45 指标 一次失败引发两次热修复，失败部署分子为 1，事故触发的返工部署分子为 2，分母按同一窗口的全部生产部署。低频服务需要更长观察窗口并报告样本，不把无样本恢复时间记为 0，更不用团队指标给个人排名。
46 平台 生成器不能在用户未知时自动迁移数据库。模板提供计划与检查，业务所有者评审兼容性，部署身份执行并留证据。异步服务另需幂等、确认/重试、积压和死信验收；同一 HTTP 探针不能覆盖全部。
47 成本 两个服务、少量维护者且允许一小时恢复，VM 或 Compose 都可能合理，需证明恢复能满足目标。明确单机故障域、维护成本和重新评估信号，例如恢复目标缩短或服务与团队增多。工具复杂度不是评分标准。
48 综合项目 过滤实现应验证三类输入与真实 SQL，保留旧调用。证据链应贯穿需求、最终提交、被验证制品、环境配置、业务结果与故障恢复。缺少的真实环境验证照实标记；没有逐章快照时保存自己的开始与结束提交。

49—56：场景选修#

专题 参考答案与检查重点
49 CI 迁移 校验身份无需发布权限；由目标平台分支/环境规则、Runner 隔离和令牌作用域共同保证。缓存、artifact、审批和取消语义不可仅按字段名等价替换。要求可信和不可信来源各有一次权限验证。
50 内网 文件哈希正确但签名失败可能是关联签名未导入、目标 manifest 改变、身份/信任根不符、时钟或离线验证材料缺失。逐层检查，不能关闭校验。还要证明干净环境不偷偷访问公网依赖。
51 云迁移 20×10=200，超过 120 连接预算；应降低最大实例、每实例池大小或调整数据库能力并留维护余量。不能只把数值改到恰好 120，还需计入迁移、运维、峰值和连接释放行为，以负载验证。
52 网格 mTLS 确认身份与加密，授权限制哪个身份能访问什么。账单服务限制仍需要 AuthorizationPolicy 或业务授权，并验证合法身份成功、不允许身份失败、明文失败三类结果。
53 传统应用 先解决共享目录单写者假设、启动和就绪行为、兼容性及回退。不能直接把副本数改为 2 宣称滚动发布；若只能单实例，应评估停机窗口或改造状态依赖，再选择发布策略。
54 异步 效果已提交而去重表未提交时崩溃，重投会再次产生效果。将去重与同库效果纳入同一事务可覆盖本例边界；外部邮件或支付不在同一事务，需要幂等接口与不确定状态处理。
55 AI 辅助 先检查 hostname、证书链、有效期、时钟和 CA 配置，修复信任路径。关闭验证削弱身份保证，不应为让任务变绿而默认接受。要求 AI 提供最小证据与 diff，并在隔离环境复验。
56 AI 应用 schema 只检查结构与值域，不证明语义正确。增加独立退款案例、类别混淆统计及业务损失阈值，保留未参与调优的评测集；真实模型要重复评估。回退整个模型/Prompt/代码组合才能解释结果。

综合验收怎样判定#

评审先检查“证据是否真实、范围是否匹配”，再检查功能是否满足目标。任何未执行项不能用预期输出代替；模拟数据与真实数据分开。若无法证明同一制品、数据恢复或负例拒绝，先补这些关键缺口，再优化页面截图和报告排版。

建议把每次失败也纳入学习记录：观察到了什么、排除了什么、最小修复是什么、怎样确认恢复。这样你的成果能成为下一位读者可复现的操作材料，而不仅是一次个人成功经历。
