成本、生产就绪与架构取舍

学习目标比较 VM、Compose、Kubernetes 三种方案；完成成本模型与生产就绪审查，列出尚未满足的条件
本页目录前置与评审输入三种方案的工作清单一个可复算的成本模型成本与可靠性相互约束生产就绪不是一个绿色勾选框故意遗漏一个成本与依赖验收、练习与参考

TicketDesk 在本机运行成功，只证明一条开发路径可用。把它放到生产还需要身份、容量、备份、运维交接和预算。选择 VM、Compose 或 Kubernetes 时，应回答“它解决了什么问题、谁能维护、失效后怎样恢复”，并把省下的工作和新增的工作同时算进去。

前置与评审输入#

先完成 云资源规划、容量实验 和 恢复演练。准备访问模式、数据敏感程度、允许停机时间、团队规模和维护时段。没有这些约束，单纯比较每月主机价格无法得出合适架构。

本章提供成本模型与生产就绪判断，数字均为教学假设，不是任何供应商的报价。真实预算需按区域、购买方式、流量方向和当前价格重新计算并注明日期。

三种方案的工作清单#

方案 适合评估的情境 团队仍要承担的工作 升级到下一种的信号
VM + systemd 服务少，部署结构清楚，团队熟悉主机 OS 修补、依赖、进程、证书、容量和备份 配置漂移和环境复制成本明显增加
单机 Compose 小规模容器应用，接受主机故障恢复时间 宿主机、磁盘、网络、跨主机容灾和发布脚本 单机容量或故障域不满足业务目标
Kubernetes 多服务、多团队，需要控制器和统一策略 集群升级、CNI/CSI、策略、资源治理和排障 不是必经终点，应评估是否有足够维护能力

托管数据库能转移部分维护工作，但应用仍需负责权限、连接、schema、恢复验证和费用。托管 Kubernetes 也不会自动替你设计应用 SLO。架构选择应包含“暂不增加复杂度”的选项，并写明以后重新评估的触发条件。

一个可复算的成本模型#

月成本可以按计算、存储、备份、网络、观测、支持和人工时间分项。下面使用任意“成本单位”，避免被误读为云厂商价格：

计算：2 个实例 × 730 小时 × 0.06 单位/小时 = 87.60
主存储：100 GB × 0.10 单位/GB·月 = 10.00
备份：200 GB × 0.03 单位/GB·月 = 6.00
出网：50 GB × 0.08 单位/GB = 4.00
观测与支持：固定 20.00
直接成本合计：127.60 单位/月
维护：6 小时/月 × 内部时间成本，另列而不冒充账单

730 小时是这里的估算常量，不代表每月精确小时数。应加入峰值扩容、双环境、备份增长和异常流量的敏感性分析。把实例缩到一台看似省钱，却可能使既定恢复目标失效；应在同一服务目标下比较。

成本与可靠性相互约束#

资源 request 影响调度，limit 影响运行上限，实际利用率影响是否浪费。不能因为 CPU 平均值低就删除冗余：它可能是故障切换容量。反过来，给所有 Pod 申请极大的内存，会让集群扩容而业务未获益。

观测也有成本。日志保留时长、trace 采样率和高基数指标都可能放大存储与查询量。对 TicketDesk，先规定不记录请求正文、限定路由标签、区分实验与生产的保留策略，再用采集量验证预算。降低采样前应确认仍有足够信息排查关键故障。

设置资源 owner、环境和到期日标签，定期清理临时环境。自动清理必须先识别状态性资源：数据库卷和备份不能只因“七天没部署”就删除。为重要数据设置独立保留策略和恢复验证。

生产就绪不是一个绿色勾选框#

使用 templates/production-review.md 记录每项证据、负责人和剩余风险。对 TicketDesk 基线，以下条件尤其重要：

领域 放行所需证据 本教程实验基线的边界
访问 身份认证、对象授权、TLS、速率控制经过检查 工单 API 没有用户认证，仅供隔离实验
数据 备份恢复、迁移兼容、保留和删除规则 本地转储流程不能证明生产恢复目标
容量 与实际流量相似的压力与降级实验 短时本机压测不等于容量承诺
发布 同一 digest 晋级、业务验证、已演练回退 云端和真实集群尚需环境验证
运行 服务所有者、告警送达、Runbook、值班安排 示例 Alertmanager 没有外部通知接收者
安全 凭据生命周期、供应链校验、漏洞修复过程 离线策略检查不能替代准入控制

必须项未满足时，结论可以是“仅限预发布实验”，并列出可关闭的差距。风险接受需要有权承担业务影响的人确认，不能由工具自动生成一句“已合规”。

故意遗漏一个成本与依赖#

假设计算账单符合预算，却因为保留全部 debug trace 导致存储持续增长。检查每日摄入量、保留时间、查询需求和实际账单归属；先停止无必要的详细采集，再验证关键诊断能力仍可用。只关闭全部观测会把问题转移到下一次事故。

第二个练习是服务器丢失后尝试按运行手册恢复。如果证书私钥、DNS 权限或备份密钥只在故障主机上，备份文件完整也无法按时恢复。把这些依赖补入恢复顺序及独立保管机制。

验收、练习与参考#

提交三方案对照、可复算月成本、一个敏感性分析和有证据的就绪评审。练习：在“两个服务、两名维护者、允许一小时恢复”的教学条件下选择方案，并列出改变选择的两个信号。答案并非固定选某项工具，判断方法见 参考答案。
