企业内网与自托管交付

学习目标用一套选定组合完成内网交付；依赖清单、镜像导入与更新过程可校验
本页目录谁需要这条路径先画依赖方向先准备 Python 依赖包导入镜像与校验内容更新、过期与扫描数据库故障和恢复演练交付与练习

网络不能访问公共 registry 时，简单替换一个镜像地址往往仍会失败：基础镜像、Python wheel、CI 组件、扫描数据库、证书链甚至时间同步都可能依赖外部系统。本专题选择“内部 GitLab + Harbor + Python 包仓库”的代表组合，设计一条可核对的离线导入与更新路径。

谁需要这条路径#

适用于有明确网络边界、长期维护人员和更新责任的组织。前置是 制品标识、备份 和 供应链。额外成本包括每个自托管服务的数据库、存储、证书、升级、备份和故障恢复。仅因为工具免费就自托管，通常低估了这些工作。

本专题提供导入清单与操作方法，不含你组织的内网地址、CA 或审批流程，也没有在真实隔离网络部署该组合。

先画依赖方向#

消费方 需要的内容 允许来源与更新责任
Runner Git、执行镜像、构建工具 内部 Git 与制品平台，平台团队维护
镜像构建 基础镜像、wheel、系统软件包 经导入检查的镜像与包源
安全扫描 工具、漏洞数据库及时间信息 受控更新源，记录数据库生成时间
部署环境 应用镜像、运行配置、证书 只读拉取，部署身份与构建身份分开
恢复环境 Git 数据、registry 元数据和 blob、配置 独立备份位置与恢复说明

域名解析、内部 CA 与 NTP 是基础依赖。即使文件都已经导入，证书不受信任或时钟偏差仍可能破坏 TLS 和签名验证。不要通过全局关闭证书校验来“修复”内网问题。

先准备 Python 依赖包#

在与目标 Python 版本、OS 和架构匹配的联网构建环境中执行：

python -m pip download --only-binary=:all: \
  --dest wheelhouse -r requirements.txt
python -m pip install --no-index --find-links=wheelhouse \
  -r requirements.txt

第二条应在新的虚拟环境中验证，避免已经安装的依赖掩盖缺包。--only-binary 让缺少可用 wheel 的包明确失败；如果组织允许源码构建，应另行记录编译器、头文件、系统库和构建产物，不能悄悄依赖联网编译。

这只是应用 Python 层的依赖检查。Dockerfile 的基础镜像及可能的系统软件包仍需独立准备；使用 macOS 或不同 CPU 下载的 wheel 也不一定能在 Linux Runner 上安装。

导入镜像与校验内容#

联网区记录来源仓库、精确 digest、平台、扫描与来源信息，按组织流程导入隔离区。docker save / docker load 可用于搬运选定本地镜像，但导入目标 registry 后，应重新解析目标引用并确认 manifest、平台和关联证明，不能只比较 tag 字符串。

对传输文件生成校验清单，例如在待传输目录中用 sha256sum 为镜像归档与 wheel 生成列表；清单应通过独立可信渠道校验或签名。文件哈希只能检测内容是否与清单一致；若清单也被一起替换，它不会证明来源可信。

多架构索引、签名、SBOM 和其他 OCI 关联制品可能需要专门的复制工具与配置。不要假设一次 save/load 自动搬走所有关联对象。把“能启动指定平台的镜像”和“完整保留供应链验证材料”设为两个验收项。

更新、过期与扫描数据库#

为依赖建立周期：发现更新、分析影响、导入候选、隔离扫描、测试、晋级、保留旧版本、回退。离线网络不能变成永不更新的理由。记录扫描器版本、数据库时间、扫描时间与制品 digest；数据库过旧时，应按策略标为证据不足，而不是“没有漏洞”。

内部仓库权限至少区分导入者、构建者和运行拉取者。可变 tag 的覆盖规则、制品保留和垃圾回收要与回退保留窗口一致。先在实验项目验证清理规则，避免删掉仍在运行的版本或证明材料。

故障和恢复演练#

先移除一个目标平台所需 wheel，断开外部包源后安装应失败且指出缺包；补回后在干净环境重试。再用未信任内部 CA 的客户端访问实验 registry，确认失败原因是证书信任，并通过安装受信任 CA 修正，保留 hostname 校验。

最后将 Harbor 恢复到独立实验环境，验证登录权限、项目配置、镜像拉取和目标 digest。只备份存储目录却遗漏数据库或关键配置，可能无法恢复完整服务。具体备份方式取决于部署形态，参考 Harbor 备份恢复文档，不要把 Kubernetes 的恢复工具直接套到其他安装方式。

交付与练习#

提交依赖清单、校验清单、证书信任路径、更新日历、恢复结果与责任分工。独立验收是在不能访问公共依赖的测试环境完成新建构建、拉取、运行和恢复，且能指出所有未消除的外部依赖。

练习：导入文件校验成功但镜像签名验证失败，列出三类不同原因。见 答案。继续查阅 pip download 与 OCI 镜像规范，为实际平台建立版本化导入记录。
