威胁模型、身份和密钥生命周期

学习目标画出开发者、CI、部署器和应用的权限；让越权操作失败；轮换实验密钥并验证服务恢复
本页目录1. 画出资产与信任边界2. 认证与授权分别验证3. 用短期身份减少长期秘密4. 秘密从创建到撤销都有责任5. 设计一次完整轮换6. 威胁模型要导向具体改进7. 验收

交付链能够把代码带进运行环境，也可能把错误身份、泄露凭据或未经审阅的变更带进去。威胁模型先说明要保护什么、信任在哪些边界发生变化，再决定哪些控制值得实现。

本章围绕 TicketDesk 的源码、流水线、制品、部署器、应用与数据库。目标是形成权限与轮换方案，不要求引入所有安全产品。

1. 画出资产与信任边界#

重要资产包括源代码完整性、发布权限、制品身份、业务数据和恢复材料。边界出现在开发者提交、PR 执行、CI 获取凭据、部署器读取环境配置、应用访问数据库等位置。

身份 必要能力 通常不需要的能力
PR 检查器 读取源码、执行隔离测试 生产部署与秘密读取
发布构建器 构建并写指定制品仓库 修改组织所有权限
环境协调器 读取指定仓库、管理授权目标 管理所有集群与命名空间
应用 读写自己的业务数据 读取全部集群 Secret
备份任务 读取备份所需数据、写指定存储 随意删除所有历史备份

权限既要看 API 动作，也要看资源范围、运行环境和输入来源。不可信 PR 内容被高权限工作流执行，是需要重点检查的边界之一。

2. 认证与授权分别验证#

认证回答“是谁”，授权回答“允许做什么”。可以成功获取身份信息，不代表应该拥有数据库管理权限；能读取某个仓库，也不意味着能部署它的任意分支。

用正反例验证：构建器能推送自己的候选、不能覆盖其他项目；观察者能读取 Pod 状态、不能读取 Secret；应用数据库用户能访问业务表、不能执行无关管理动作。只验证正常路径，会遗漏权限过宽。

3. 用短期身份减少长期秘密#

OIDC 可以让工作流向目标系统证明身份，再按信任策略换取短期权限。目标必须校验发行者、受众、主体及相关条件，不能只因为 token 来自某个平台就允许所有仓库使用。

GitHub Actions 中 id-token: write 允许工作流请求相应身份 token，但不自动授予云资源权限。云侧或目标系统仍需严格限定仓库、分支或受保护环境等条件。参考 GitHub OIDC。

本项目的基础 release 工作流只发布练习镜像，尚未配置云 OIDC 信任或生产部署角色。读者接入时先在隔离目标验证允许与拒绝条件，再扩大范围。

4. 秘密从创建到撤销都有责任#

秘密生命周期包含生成、存储、分发、使用、轮换、撤销与审计。每个秘密需要所属者、用途、访问范围和不再使用时的处理方式。

应用日志、镜像层、构建参数、计划文件、错误回显和备份都可能成为额外副本。删除当前文件不能撤销已经泄露的凭据；真正的处置通常需要撤销或轮换，并调查使用范围。

不要把 secret 名称当成秘密值写进文档。教程中的记录保留标识和版本，不保存内容；复制调试输出前检查连接串、认证头和环境展开。

5. 设计一次完整轮换#

先确认哪些消费者使用旧身份，再准备新的受限身份或凭据；在允许的过渡条件下更新部分消费者并验证；完成切换后撤销旧身份；最后验证旧凭据失败、新业务成功以及恢复材料得到更新。

如果目标系统不支持并行身份，轮换可能需要维护窗口或其他协调方式。数据库初始化密码环境变量也不等于账号密码管理 API，不能通过只改 Secret 完成整个轮换。

6. 威胁模型要导向具体改进#

选择两个与当前项目最相关的风险，例如 PR 工作流读到发布凭据、被替换的镜像进入环境。为每项写清攻击或误用前置、当前控制、验证方法和剩余风险。

不要把所有想象中的威胁都列成必须立即采购的产品。优先解决高影响且与现有边界直接相关的问题，并把控制放到代码评审、身份、制品或运行等恰当位置。

7. 验收#

提交资产与边界图、身份矩阵、至少一组越权拒绝证据、轮换计划及实际执行范围。对尚未接入的云身份保留设计状态，不将本地 RBAC 检查说成整条云权限链已经通过。
