本页目录最短部署路径接入已有导航上传后检查什么修改内容后如何重新生成与个人站样式逐步融合

网站采用静态 HTML、CSS 和 JavaScript，所有站内页面与资源使用相对路径。可以放在个人网站的 project/devops-guide/ 子目录，形成 https://zhangjian94cn.top/project/devops-guide/index.html。这是建议接入路径，当前并未写入或修改该域名上的文件。

最短部署路径#

下载静态网站部署包（当前解压版本），解压后得到 devops-guide/。将这个目录上传或复制到个人网站发布目录的 project/ 下，保留 index.html、章节 HTML、assets/ 和 downloads/ 的相对位置。

不需要数据库、Node 服务或额外后台。网站也不请求外部字体、统计服务或 CDN 脚本。若个人站由 Git 构建发布，把文件放进该项目真正会复制到最终输出的静态目录，并沿用现有的发布流程。

不要仅上传 index.html。首页依赖样式与阅读脚本，章节和附件也都有自己的路径。部署前保留原站版本，部署后从完整子目录 URL 开始检查。

接入已有导航#

在个人网站的项目或教程列表中增加链接：

<a href="/project/devops-guide/index.html">DevOps 实战手册</a>

这个根路径链接适用于所给域名的站点结构。如果你的个人站实际部署在更深的公共基路径下，按现有站点规则调整入口；教程内部的相对链接无需改成绝对地址。

不要直接用教程页面覆盖现有 Git 教程。两份内容分别放在 git-guide/ 与 devops-guide/，再从主站导航关联。

检查场景 预期结果
直接打开第 48 章和专题 56 URL 无需先访问首页，正文与样式正常
浏览器刷新章节页 页面仍能打开，不依赖前端路由回退

若样式或脚本返回 404，先看实际上传目录和大小写，再检查服务器缓存。复制功能优先使用浏览器剪贴板 API，环境不支持时尝试传统复制；失败会提示手动选择，不显示虚假的成功。

修改内容后如何重新生成#

下载网站源码，安装满足 marked 要求的 Node 运行环境，然后在源码根目录执行：

npm ci
npm run build
python3 tools/package_downloads.py
npm run check

修改 content/chapters/01.md 等文件更新正文；修改 content/pages/ 更新导读、答案、术语、排障与接入说明；样式和阅读交互位于 assets/。输出在 dist/，它的内容就是静态发布文件。

主线正文位于 content/chapters/01.md 至 48.md；专题位于 content/electives/49.md 至 56.md。目录和搜索索引由构建脚本生成。新增正文后同时更新版本、验收状态和阶段说明，不能只让目录看起来已完成。

先 build 生成 HTML，再 package 生成附件，最后 check 检查附件与页面引用。部署包不嵌套包含自身。解压版本将“下载部署包”的自身入口替换为文字说明，其余项目、模板和源码下载保留；重新生成时脚本会排除旧的部署 ZIP。

与个人站样式逐步融合#

当前站点采用独立阅读布局：章节目录、正文、本页目录、搜索和上一章/下一章。通过 CSS 变量可以调整强调色、文字色和页面背景；页眉中的个人主页地址可以在生成脚本中维护。

若后续提供个人站源码，可把相同正文与资料接入现有模板、导航和发布流水线。保留章节文件名和外部可访问 URL，有助于已有链接和读者收藏继续有效。当前交付先确保内容与网站结构可以独立维护和迁移。
