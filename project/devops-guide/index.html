根据自己的起点选择路径#

刚接触工程实践：从第 01 章顺序阅读。第 03 章先运行服务，第 13—15 章再拆开解释容器机制。遇到陌生术语查术语对照，无需一次记住所有工具。

已经会开发应用：先读第 01、03、04 章建立共同背景，自测第 05—11 章，重点完成第 12—20 章交付闭环。随后按工作需求选择集群、观测、安全和平台部分。

有运维经验，想补交付工程：重点完成需求验收、Git、测试分层、制品身份和数据兼容，再进入 IaC、GitOps 与可靠性。把手工操作改成输入清楚、失败可见、结果可验收的步骤。

技术负责人或架构读者：先读第 01、04、37、40、45—48 章，关注目标、责任、恢复与维护成本，再返回具体实现。不要按团队安装工具的数量判断能力。

每章怎么学#

先读场景和机制，再在自己的练习环境执行步骤。保留真实输出；失败时参考故障速查定位层次。完成练习后再看答案与验收提示，最后提交本章要求的材料。

区分已读、已执行、已验收：理解文字不等于运行过，运行过不等于结果满足条件。可以下载学习记录表管理进度，无须注册账号。书中交互用于解释请求路径、健康、流水线、制品身份和 SLO 预算，不操作真实环境。

终端示例默认 Linux、macOS 或 Windows WSL2 的 Bash；systemd 章节需要对应 Linux 环境。未特别说明时，项目命令从解压后的 ticketdesk/ 执行。集群命令限定实验 context，云实验先明确身份、预算和清理范围。

围绕同一个项目实践#

TicketDesk 使用 FastAPI 与 PostgreSQL，提供 API、简单页面、测试、迁移、Docker/Compose、CI 和恢复脚本。进阶资料包括 OpenTofu、Ansible、Kubernetes、Helm、GitOps、Prometheus/Grafana、可选 OpenTelemetry、离线安全门禁，以及异步与 AI 评测教学示例。

基础 API 没有登录与业务授权，指标在进程内累计，数据库也是教学部署。各章节给出改进方向和验证条件；它不是可以直接向公众开放的生产工单系统。

本版已执行 16 项 Python 测试及 23 项离线示例检查。容器、真实 PostgreSQL、云、集群与托管 CI 仍需在相应环境完成实验。查看配套资料下载项目与记录模板。
