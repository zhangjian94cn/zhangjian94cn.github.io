CHAPTER 34 · 第 9 篇v0.3 阅读版

Prometheus、PromQL 与 Grafana

学习目标用固定工作负载建立仪表盘；验证请求量、错误率与延迟变化；识别错误聚合导致的误判
本页目录1. 三类指标的读法2. 启动本地观测栈3. 速率与错误比例4. 延迟分位数来自桶，而非平均值5. 固定工作负载再比较图形6. 图表与数据保留的常见误判7. 验收

应用的 /metrics 暴露某个时刻的测量，Prometheus 定期抓取并保存时间序列，Grafana 使用查询结果表达趋势。本章让每张图都能回答一个明确问题，并解释空值、计数重置与分位数的边界。

前置是已运行的 Compose 应用。配套 observability/ 提供采集、规则、数据源和仪表盘；镜像版本是待集成验证的固定候选，尚未在作者环境启动这套服务。

1. 三类指标的读法#

Counter 表达累计事件，通常随事件增长并可能在进程重启后重置；Gauge 表达某一时刻的数值，可增可减；Histogram 表达样本分布。

v0.3 为请求耗时增加经典直方图，按方法、路由与状态记录累计桶、总和和样本数。已有的总和/数量仍可算平均值，但不能单独恢复 p95。本教学例保留经典桶便于观察；实际选型应核对库和服务端对原生直方图的支持，而不是假定经典桶永远是首选。参考 Prometheus 直方图与摘要。

2. 启动本地观测栈#

python3 scripts/observability_init.py
docker compose -f compose.yaml -f observability/compose.yaml up -d prometheus grafana alertmanager collector

Prometheus 在本机 9090，Grafana 在 3000，Alertmanager 在 9093。Grafana 使用单独生成的本机密码，查看自己 .env 中对应值登录，不把密码放进截图或日志。端口只绑定回环地址。

在 Prometheus Targets 页面确认 app:8000 可抓取。容器中的地址不是你浏览器的 localhost。Grafana 的数据源使用 Compose 服务名连接 Prometheus，并自动载入本书四个基础面板。

3. 速率与错误比例#

创建工单每秒完成多少 HTTP 请求：

sum(rate(ticketdesk_http_requests_total{job="ticketdesk",method="POST",route="/tickets"}[5m]))

rate 处理一段时间内的计数变化，先对各序列求速率，再聚合，可保留对单实例重置的合理处理。时间窗口太短或样本不足时，图可能不稳定或没有结果。

5xx 比例需要分子与分母口径一致。配套面板将创建路径 5xx 速率除以该路径请求速率；它衡量这一技术范围，不自动等于用户旅程 SLO。没有 5xx 序列时可按明确约定显示 0，但必须同时查看 up 和请求量，避免把数据缺失涂成成功。

4. 延迟分位数来自桶，而非平均值#

histogram_quantile(0.95,
  sum by (le) (
    rate(ticketdesk_http_request_duration_seconds_bucket{job="ticketdesk",method="POST",route="/tickets"}[5m])
  )
)

经典桶是累计的，le 表示桶上界。聚合时保留 le，使函数能重建近似分布；不同实例应采用兼容的桶边界。这个 p95 是估计值，精度受桶和样本分布影响。

平均多个实例各自的 p95，通常得不到整体 p95。两组请求数量不同，简单平均尤其容易误导。若某个业务阈值很重要，应在其附近安排合适桶边界，并用阈值内成功样本比例直接回答目标问题。

5. 固定工作负载再比较图形#

python3 scripts/load.py --requests 100 --concurrency 4

脚本只允许回环实验地址，有请求与并发上限，会创建虚构工单。记录实际状态码、总耗时与采样方式；它是闭环负载，并非固定到达率压测器。

保持资源、数据规模、版本与查询时间范围一致，先运行基线，再改变一个因素。观察请求速率、错误与延迟是否对应真实变化。短负载结束后，五分钟窗口会继续包含此前样本，不能期待图立即归零。

6. 图表与数据保留的常见误判#

空白可能是没有数据、标签不匹配、目标失联或窗口样本不足。累计 Counter 下降可能是进程重启。面板纵轴自动缩放可能让小变化看起来巨大。把错误率单位设成百分比时，还要确认输入是 0—1 还是 0—100。

本例只保留六小时指标，用于学习。生产保留需要考虑排障周期、容量、基数、备份与访问策略，不能把无限保留当成默认。新增环境时，为查询明确限定服务与环境，避免无意聚合不同系统。

7. 验收#

提交四张对应真实问题的面板、查询解释、固定负载记录和一次目标停止后的观测。验证停止目标产生不可达信号，恢复后业务仍可用。仪表盘 JSON 随配套项目提供；截图可以辅助说明，但原始查询与数据口径才是可维护成果。
