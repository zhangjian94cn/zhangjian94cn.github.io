传统应用与不同语言的交付改造

学习目标选择一个传统应用，用相同验收框架完成自动构建、部署、观察与回退
本页目录前置与原始约束构建工具不同，验收原则相同先固定 Java 构建入口把部署改成可恢复的目录切换Windows、共享文件与长启动故障实验与回退边界验收、成本与练习

一套运行多年的 Java 应用可能依赖固定目录、人工复制 JAR、共享上传文件和手工数据库脚本。第一步不一定是迁进 Kubernetes，而是让当前部署可重复、可追溯、可恢复。本专题选择“Java HTTP 服务继续运行在 VM，由 systemd 管理”的渐进改造案例。

前置与原始约束#

前置是 Linux 进程、自动化配置 和 兼容迁移。需要一个你有权修改的实验 Java 项目、匹配它的 JDK、已提交的构建配置和可丢弃 VM。本章的 Java 命令是代表性操作，不是 TicketDesk Python 仓库中已经存在的 Java 模块。

先记录启动时长、配置来源、上传目录、定时任务、外部依赖和停机限制。无法说清这些，就很难判断容器化是否改变行为。把生产文件直接复制到实验环境也可能带入客户数据或凭据，应使用合成样本。

构建工具不同，验收原则相同#

生态 构建和依赖常见入口 需要验证的差异
Java Maven / Gradle wrapper、依赖管理 JDK、构建插件、JAR 与 JVM 参数
.NET SDK 与 NuGet restore/publish 目标 runtime、IIS 或服务托管、平台依赖
Node.js package.json 与包锁文件 安装脚本、运行时版本、构建和运行依赖
Go go.mod、go.sum、编译产物 工具链、CGO、目标 OS/架构

不要只保留源码提交而漏掉构建工具和锁定信息。也不要在每台服务器现场编译：在受控环境生成候选制品，测试并记录摘要，再把同一份候选部署到各环境。

先固定 Java 构建入口#

若项目已采用可信且提交到仓库的 Maven Wrapper，可在项目根执行：

./mvnw --version
./mvnw --batch-mode clean verify

确认输出的 Java 与 Maven 版本符合该项目要求，审查 wrapper 配置的分发地址。verify 是否包含集成测试取决于项目插件与测试组织，命令成功不能自动证明已经测试数据库或外部依赖。构建产物名称也由项目决定，应从构建配置解析，避免用 target/*.jar 随机选择多个文件。

对确定的发布 JAR 计算 SHA-256，保存源码提交、依赖清单、构建环境和测试报告。JAR 摘要与容器 digest 是不同对象；如果之后再装进镜像，要记录两者关联。

把部署改成可恢复的目录切换#

在 VM 中区分只读发布目录、外置配置和持久数据，例如 /opt/example/releases/<release-id>、/etc/example/app.env 与 /var/lib/example。应用使用独立低权限用户；发布目录由部署者写入，运行用户不应修改自己的程序。

systemd 单元的 ExecStart 指向明确的 Java 路径和发布 JAR，配置通过受保护环境文件或应用支持的配置机制注入。上传文件不放在发布目录。先部署新目录、验证校验值、更新引用并重启，再验证就绪和业务；失败时回到上一份程序及相容配置。

目录切换可以使文件引用变化原子化，但不会让进程替换或数据库迁移自动原子化。长启动服务可能产生明显不可用窗口；需要高可用时，可评估双实例、入口摘流和逐个替换，并实测容量。

Windows、共享文件与长启动#

IIS 应用池、Windows 服务账户和 ACL 不能机械套用 systemd。保持相同验收目标：受限身份、可追溯制品、配置分离、健康检查、日志、回退和数据验证，再使用对应平台工具实现。维护团队熟悉哪种平台，本身就是成本条件。

共享文件需要回答并发写、权限、备份和挂载不可用时的行为。把共享目录改成对象存储属于业务适配，不应作为“透明容器化”悄悄完成。长启动应用则要区分启动探针、存活和就绪，避免启动期间被反复重启。

故障实验与回退边界#

先把实验服务的数据库连接配置改错，检查它是否明确未就绪、日志是否能关联错误，又不会泄露完整凭据。恢复旧配置后验证既有记录仍可读写。再让构建产物校验不匹配，部署应在切换之前停止。

如果新版本已经执行破坏性 schema 迁移，切回旧 JAR 可能无效。采用先扩展、再迁移使用方、最后清理的兼容策略，并单独评审数据变更。备份恢复也不是随意回退按钮：恢复时间点之后的新写入如何处理，必须提前决定。

验收、成本与练习#

新增维护成本是构建环境、制品仓库、运行单元、脚本和升级责任；收益应体现为减少手工步骤及缩短恢复。独立验收是在空白实验 VM 部署同一制品、完成业务检查、注入配置故障并恢复，且持久文件和记录保持正确。

练习：一个应用启动三分钟、只能单实例访问共享目录，应先解决什么，再谈滚动发布？参考 答案。进一步核对 Maven Wrapper 和 systemd.service，把命令适配到明确版本的真实项目。
