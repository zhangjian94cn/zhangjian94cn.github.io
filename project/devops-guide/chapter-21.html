云平台、身份、网络和费用

学习目标必做能力映射和成本估算；可选建立最小云环境，验证访问边界并列出清理后的剩余资源
本页目录1. 先分配责任，再选择产品2. 认识区域、可用区和依赖范围3. IAM 先回答“谁能做什么”4. 把网络画成允许的路径5. 成本模型至少算到清理结束6. 最小云实验与清理7. 本章验收

本机恢复演练通过以后，团队希望其他人也能访问 TicketDesk。此时新增的问题不是“选一台更大的机器”，而是谁能创建资源、哪些请求能进入、数据落在哪里、资源关闭后是否继续收费，以及故障由谁处理。

前置是第 20 章的交付闭环。本章必做内容是能力映射与环境设计，不要求开通付费账户。可选实操仅在自己的隔离实验账户进行；本教程没有替你创建任何云资源。

1. 先分配责任，再选择产品#

托管服务把某些运行职责交给平台，并不会把所有责任转移出去。使用托管数据库之后，平台可能维护宿主机与数据库基础软件，你仍需处理账号权限、schema、查询、数据保留与业务恢复。

能力 VM 方案中的承担者 托管方案中仍由你承担的部分
操作系统补丁 自己维护 应用依赖与运行配置
数据库运行 自己安装、升级与监控 schema、访问、备份策略与恢复验收
流量入口 自己维护代理 证书、路由、访问范围与超时策略
数据持久化 自己管理磁盘 保留策略、加密授权与数据完整性
事件处理 自己发现并恢复 用户影响判断、沟通和业务验收

先写清责任，再比较产品能减少哪些工作。架构讨论可以借助 AWS Well-Architected 的维度，但本项目的取舍依据是规模、预算和团队能力。

2. 认识区域、可用区和依赖范围#

区域通常对应一个地理范围；可用区用于在区域内分隔部分故障风险。两个实例位于不同可用区，可以降低单个可用区故障的共同影响，但如果仍依赖一份单点数据库，业务仍可能整体不可用。

对象存储、负载均衡、数据库和密钥服务各有自己的可用性与故障域。不要仅在图上画两个方框，就把整个系统标成“高可用”。还要检查入口、数据库、身份、DNS、恢复材料和操作通道的依赖。

实验设计应写出三种故障：一台应用主机消失、数据库不可用、整个实验环境被误删。分别需要应用副本、数据库恢复能力，以及独立保存的代码和恢复资料。

3. IAM 先回答“谁能做什么”#

把人的登录身份、CI 构建身份、部署身份和应用运行身份分开。构建器只需读取源码与写入指定制品仓库；应用只需访问自己的数据库与必要对象；发布器才有目标环境的变更权限。

优先使用平台支持的短期身份，避免共享长期管理员密钥。权限策略要限定动作、资源与条件；允许操作一台应用机器，不应顺便允许修改整个账户的身份策略。

如果选择 AWS 路线，在已配置好的自己的账户中，可先执行身份确认：

aws sts get-caller-identity

将实际账号、角色和区域与实验计划对照，再进行变更。身份确认是读取，不是创建权限的证明。预算提醒也不是权限控制，不能阻止所有超额资源被创建。

4. 把网络画成允许的路径#

VPC 是云上的逻辑网络边界；子网划分地址与区域范围；路由决定下一跳；安全组或对应过滤机制决定哪些流量被允许。名称不同的平台需要重新核对语义，不能照搬规则格式。

本项目的目标路径可以写成四条：用户经 HTTPS 到入口；入口访问应用端口；应用访问数据库端口；受控管理身份通过管理通道维护资源。数据库不需要为了“方便调试”向所有公网地址开放。

来源 目标 必要访问 验证
测试用户 HTTPS 入口 443 证书验证与业务请求
入口组件 应用 实际监听端口 就绪和业务路径
应用身份与网络 数据库 数据库端口与账号权限 正确访问成功，越界访问失败
运维身份 管理通道 明确的维护动作 审计与最小权限

公网 IP、互联网路由、监听地址、过滤规则和应用身份是不同条件。只改其中一个，可能仍然访问不了；全部放开则会得到一个难以解释的边界。

5. 成本模型至少算到清理结束#

成本由计算时长、磁盘、快照、数据库、负载均衡、出口流量、日志与其他托管服务共同组成。停止 VM 可能只停止计算部分，附加磁盘、IP、快照或入口仍可能计费。

使用当前目标区域的官方价格填入下表，不在教程中把示例数当成报价：

项目 单位 数量或时长 估算方式
计算 每实例小时 实例数 × 小时数 单价 × 用量
存储 每容量月 容量与保留时间 按平台计费规则估算
网络 每传输量 出口及跨边界流量 单价 × 传输量
观测 摄入、查询与保留 日志和指标规模 各项分别计算

为实验资源标注项目、环境、负责人和到期时间。开通预算与异常提醒，并说明接收者；提醒触发延迟、免费额度条件和销毁后的剩余项都要核对。

6. 最小云实验与清理#

可选路线是单台实验 VM 加受控入口，数据库仍限于实验用途。先完成身份和费用记录，再创建网络与机器，部署同一候选 digest，验证访问边界和指定工单。无认证的教学应用不应直接开放给公众；使用已有的受控访问入口或保持管理通道内可达。

实验结束先保存需要的恢复材料，移除应用与入口，再核对磁盘、快照、地址、密钥、日志和数据存储。使用资源清单与账单视图交叉核对，不能只看虚拟机列表为空。

7. 本章验收#

交付一页架构、责任表、身份矩阵、网络允许路径、费用估算与清理清单。没有云实操时，这些仍是可评审的设计材料，但状态应为“设计完成，运行待验证”。思考题：如果数据库改成托管服务，哪些恢复步骤仍必须由应用团队验证？答案见练习与答案。
