CHAPTER 42 · 第 11 篇v0.3 阅读版

代码、依赖、镜像与动态扫描

学习目标用安全的预置样例产生发现项；门禁按明确策略阻止发布；修复或记录有期限的例外
本页目录1. 按风险选择检查层次2. 把报告绑定到正确制品3. 严重程度之外还要看上下文4. 用安全的合成样例验证门禁5. 例外必须有范围和失效机制6. DAST 需要真正的测试边界7. 验收

扫描报告只有进入可解释的修复和例外流程，才会影响交付质量。不同扫描器观察的对象不同，报告之间也不能简单用漏洞数量互相比较。

本章配套提供离线报告门禁练习，使用明确标注的虚构发现项；没有声称该发现项是真实漏洞，也没有在作者环境扫描或推送真实镜像。

1. 按风险选择检查层次#

类型 观察对象 典型边界
SAST 源码和部分数据流 需要理解语言、规则与上下文
SCA 依赖与已知风险 依赖身份、版本和数据库质量影响结果
镜像扫描 系统包与应用依赖 不等于观察所有运行时行为
DAST 运行应用暴露的行为 需要受控目标、身份与测试范围
秘密扫描 凭据样式或内容线索 误报、漏报与撤销处置仍需判断
IaC 检查 资源声明与规则 声明合规不证明现实没有漂移

本机快速检查、PR 门禁、候选制品检查和定期重新扫描各有价值。已发布制品也可能在新的漏洞信息出现后变成需要处理的对象。

2. 把报告绑定到正确制品#

在有扫描器与仓库访问条件的自己的环境中，可以对真实候选 digest 运行 Trivy：

trivy image --format json --output .lab/image-scan.json "$CANDIDATE_IMAGE"

先检查命令成功，再评价报告。记录扫描器版本、漏洞数据库更新时间、目标 digest 与平台；扫描另一个标签的报告不能替代当前候选的检查。规则与支持范围参阅 Trivy 漏洞扫描。

扫描器无法下载数据库、读取镜像或完成检查时，应显示“检查失败”，不能生成一份空报告后当作“没有漏洞”。

3. 严重程度之外还要看上下文#

严重程度帮助排序，但实际处置还要考虑组件是否存在于运行路径、能否到达、所需权限、可利用条件和可用修复。没有修复版本也不等于风险可以忽略，可能需要限制入口、替换组件或其他缓解。

先确认组件身份与版本是否被正确识别，再讨论误报。不能因为修复费时就把真实发现项标成误报，也不能为了追求“零发现”删除所有检查规则。

4. 用安全的合成样例验证门禁#

配套 security/fixtures/scan-synthetic.json 模拟一条 HIGH 发现项，编号为 LAB-FINDING-001。它用于测试报告判定逻辑，不是扫描器准确性的测试。

python3 security/evaluate_scan.py security/fixtures/scan-synthetic.json \
  --expected-artifact lab://synthetic-ticketdesk \
  --exceptions security/fixtures/exception-expired.json \
  --as-of 2026-09-20

预期非零退出，因为例外已经过期。再在自己的练习副本中填写新的有期限例外，观察判定变化。不要修改原始发现项使其“消失”；记录为什么接受、谁负责、作用于哪个包和制品，以及何时复查。

5. 例外必须有范围和失效机制#

配套检查器要求发现项、包名和制品身份同时匹配，并检查负责人、理由与日期。生产流程还需对应的批准责任、补偿措施与自动追踪，不只是一个可随意编辑的 JSON 文件。

全局忽略某个严重级别会同时隐藏不相关风险。选择最小范围的例外，并在过期、制品变化或漏洞信息变化后重新评价。

6. DAST 需要真正的测试边界#

动态测试只对自己有权限的专用环境执行，使用测试身份与虚构数据，限制请求速率与有副作用的路径。登录、写入、删除和外部集成会改变测试影响，不能将任意生产 URL 放进通用扫描任务。

本项目没有配置生产 DAST。读者可以先为无效输入、未授权访问和错误处理定义可复现的验收，再选择工具完成相应范围，避免让工具默认爬取成为未经审阅的需求。

7. 验收#

提交扫描层次与风险映射、真实或合成报告的明确标识、阻断规则、修复或例外记录，以及过期例外再次阻断的证据。报告格式检查、扫描器实际执行和漏洞处置是三层工作，分别记录结果。
